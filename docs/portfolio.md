# 简历与面试使用说明

以下是个人作品表述，不虚构企业实习、线上用户或业务收益。使用前应自己运行、理解 SQL 和分析结论，并补上实际部署地址。

## 简历草稿

**Steam 游戏市场洞察｜个人数据分析项目**

- 基于 Kaggle 14.3 万条 Steam 原始记录，构建 SQL 清洗、游戏与标签关联建模、Pandas 分组分析及 Streamlit 交互展示流程；保留约 13.5 万款游戏和 118 万条标签关联。
- 识别源 CSV 表头错位并以同包 JSON 交叉核验；建立零评价、重复主键、非正式游戏和未完整年度的处理口径，使用 CTE、LAG、DENSE_RANK 和 Wilson 下界完成聚合与排名。
- 围绕价格、标签口碑、评价集中度和发行结构形成 5 个业务分析问题，使用评价门槛敏感性分析与同标签／同年份分组核验结论；实现筛选联动、明细导出和数据审计展示。

技术栈：Python、SQL（DuckDB）、Pandas、Plotly、Streamlit、Parquet、pytest。

## 面试中的四个重点

**为什么选这个业务？** 游戏发行与品类研究需要比较价格、产品供给和用户口碑，适合用公开数据回答可验证的问题。

**你解决了什么真实问题？** CSV 的 Discount 与 DLC count 表头合并，使好评、差评和标签字段错位。以 AppID 496350 对比 JSON 发现 252 好评、3 差评被错误读成 0 好评、252 差评，因此改用字段明确的 JSON 并加入回归测试。

**为什么不只计算平均好评率？** 热门游戏会支配加权指标，小样本满分也容易干扰排名。所以同时提供每游戏中位数、评价加权好评率、最低评价数和 Wilson 下界，并明确每个指标回答的问题不同。

**结论可靠吗？** ≥100 评价时，5～10 美元组好评率中位数为 85.2%；将门槛改为 20／500，该组仍居最高，但数值变化。无折扣样本中该组为 82.4%。这支持描述性比较，不能证明涨价或某个标签会带来更高口碑。标签重叠、折扣、产品预算和发售时长仍可能影响关系。

## 三分钟演示顺序

1. 首页说明数据版本与默认评价门槛，区分样本市场与完整市场。
2. 进入价格与口碑，解释箱线图、中位数与加权指标的区别。
3. 筛选熟悉的标签，查看排名和具体竞品，演示 CSV 下载。
4. 展示 SQL 的 LAG 与 DENSE_RANK，说明为什么 2026 年同比为空。
5. 展示数据质量发现及报告中的稳健性分析，最后讲下一版 AI 仅解释计算结果的设计。
